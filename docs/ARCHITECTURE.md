# Архитектура Yamget

## Пакеты

| Пакет | Ответственность |
| --- | --- |
| [`downloader_app`](../downloader_app/) | Разбирает аргументы, собирает зависимости, формирует очередь и выводит результаты CLI. |
| [`music_download`](../music_download/) | Разбирает источники, обращается к Яндекс Музыке, управляет очередью и aria2, сохраняет файлы и обновляет индекс. |

Оба пакета входят в workspace uv. Провайдер использует модели `yandex-music`, а локальные модели описывают контекст и состояние загрузки.

## Путь одного трека

1. [CLI](../downloader_app/application.py) создаёт индекс для каталога назначения, вызывает `scan()` и передаёт индекс в сервис. Провайдер разрешает источник в трек или последовательность треков.
2. [Очередь](../music_download/queue.py) запускает один движок на весь прогон и выполняет задания последовательно. Ошибка задания записывается в него, после чего начинается следующее.
3. [Сервис](../music_download/service.py) определяет целевой путь. Без перезаписи он сначала проверяет существующий целевой файл, затем ищет подходящую копию в индексе.
4. Для новой загрузки сервис получает прямую ссылку, передаёт её движку и скачивает аудио во временный `.part` рядом с целевым файлом. После передачи mutagen записывает теги, затем временный файл публикуется по целевому пути и регистрируется в индексе. Только после этого очередь отмечает задание завершённым.
5. CLI выводит результат каждого задания. Если есть ошибки или отменённые задания, команда возвращает код `1`.

## Движок aria2 и управление очередью

[`Aria2Engine`](../music_download/engine.py) запускает процесс aria2 и управляет им через локальный JSON-RPC. `aria2.addUri` возвращает GID передачи, `aria2.tellStatus` сообщает состояние и прогресс. RPC слушает loopback, случайный секрет передаётся через временный конфиг с правами `0600`. Прямые ссылки и секрет не передаются в аргументах процесса. Запуск и остановка ограничены таймаутами.

Программный интерфейс очереди поддерживает `pause(job)`, `resume(job)` и `cancel(job)`. Пауза относится к передаче аудио. При обработке метаданных отмена проверяется между операциями. Синхронные запросы и запись тегов заканчивают текущую операцию. `job.gid` и `job.progress` дают идентификатор передачи, объём и скорость. Неизвестный общий размер представлен `None`.

При досрочном выходе из обхода результатов вызывающий код должен закрыть генератор `queue.run()`, например через `contextlib.closing()`. CLI уже использует этот механизм. Одновременный повторный запуск той же очереди запрещён.

## Индекс и перенос

[`LibraryIndex`](../music_download/index.py) открывает SQLite `:memory:` на одну команду. `scan()` обходит папку загрузки и читает ID трека и альбома из ссылки в теге WOAF. `_record()` сохраняет относительный путь, ID, размер, время изменения, устройство и inode. Символические ссылки, пустые файлы и MP3 без распознаваемого источника пропускаются.

`find()` ищет по паре ID трека и альбома. При нескольких копиях проверяет их по порядку путей и возвращает первую актуальную. Строка устаревшей копии удаляется из таблицы. Скачивание и перенос обновляют индекс в рамках того же запуска.

[`relocate_file()`](../music_download/relocation.py) создаёт жёсткую ссылку по новому пути, проверяет оба имени, удаляет старое имя и обновляет индекс. При ошибке после создания ссылки `_rollback()` пытается вернуть старое имя, убрать новое и восстановить строку индекса. Изменение строк SQLite выполняется одной транзакцией, а операции с путями происходят отдельно. Если откат не удался, лог содержит оба пути. После принудительного завершения могут остаться два имени одного файла.
