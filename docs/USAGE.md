# Руководство пользователя

## Установка

Нужны Python 3.11 или новее, uv и системный пакет aria2. Проверьте, что команда `aria2c --version` доступна в терминале. На Arch Linux пакет устанавливается через `sudo pacman -S aria2`.

Выполните из корня Yamget:

```bash
uv sync --locked --no-editable
uv run --locked --no-editable music-download --help
```

Для просмотра справки токен и aria2 не нужны.

## Токен Яндекс Музыки

1. Следуйте инструкции получения OAuth-токена через браузер. [Документация yandex-music-api](https://ym.marshal.dev/token/)
2. Скопируйте значение `access_token` и введите его по приглашению Bash. Введённое значение не отображается и не попадает в историю команд.

```bash
read -rsp 'Токен Яндекс Музыки: ' YANDEX_MUSIC_TOKEN
export YANDEX_MUSIC_TOKEN
printf '\n'
```

Запускайте Yamget из этого же терминала. Для нового сеанса задайте переменную снова. Храните токен как пароль и не добавляйте его в репозиторий.

## Примеры запуска

Подставьте свои ID или ссылки вместо демонстрационных значений.

```bash
# Трек по ID
uv run --locked --no-editable music-download 123456

# Трек из конкретного издания альбома
uv run --locked --no-editable music-download 'https://music.yandex.ru/album/123/track/456'
uv run --locked --no-editable music-download 456:123

# Альбом
uv run --locked --no-editable music-download 'https://music.yandex.ru/album/123'

# Плейлист по ссылке или ключу
uv run --locked --no-editable music-download 'https://music.yandex.ru/playlists/12345678-1234-5678-9abc-123456789abc'
uv run --locked --no-editable music-download --playlist 12345678-1234-5678-9abc-123456789abc

# Плейлист с числовым ID и владельцем
uv run --locked --no-editable music-download --playlist 1000 --user USER

# Повторная загрузка с желаемым битрейтом 320 кбит/с
uv run --locked --no-editable music-download 123456 --bitrate 320 --overwrite
```

Один числовой позиционный аргумент означает ID трека. Для альбома целиком используйте ссылку. Ссылки принимаются по HTTPS с доменов `music.yandex.ru`, `music.yandex.com`, `music.yandex.kz` и `music.yandex.by`.

## Параметры CLI

| Параметр | Назначение |
| --- | --- |
| `source` | ID трека, пара `трек:альбом`, ключ плейлиста или ссылка. |
| `--playlist` | Ключ или ссылка на плейлист. Числовой ID передаётся вместе с `--user`. Используется вместо позиционного источника. |
| `--user` | Владелец плейлиста с числовым ID. |
| `-o`, `--output` | Корень загрузки. По умолчанию `downloads`. |
| `--bitrate` | Желаемый битрейт MP3 в кбит/с. Допустимы `64`, `128`, `192`, `320`. Если значение не указано или недоступно, выбирается максимальный доступный битрейт MP3. |
| `--overwrite` | Скачать трек заново и заменить целевой файл после успешной загрузки и записи тегов. |
| `--path-template` | Относительный путь без расширения. По умолчанию `{title}`. |
| `--log-level` | Уровень логирования. Допустимы `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. По умолчанию `INFO`. |
| `-h`, `--help` | Справка CLI. |

## Шаблоны путей

```bash
uv run --locked --no-editable music-download 123456 --output ./music \
  --path-template '{artist}/{album}/{track_number:02d} - {title}'
```

Пример результата — `music/Исполнитель/Альбом/03 - Песня.mp3`.

| Поле | Значение |
| --- | --- |
| `{artist}` | Первый исполнитель трека. |
| `{album}`, `{album_id}` | Название и ID выбранного альбома. |
| `{title}`, `{track_id}` | Название и ID трека. |
| `{year}` | Год выпуска. |
| `{track_number}`, `{disc_number}` | Номера трека и диска в выбранном альбоме. |

Числовые поля можно дополнить нулями, например `{track_number:02d}`. При отсутствии данных используются `Unknown artist`, `Unknown album`, `track`, `unknown` для ID альбома и `0` для чисел. Поля для названия плейлиста нет.

Разделитель папок — `/`. Имена из метаданных очищаются, поэтому слеш в названии песни не создаёт папку. Абсолютные шаблоны, `..` и неизвестные поля отклоняются. Итоговый путь должен оставаться внутри `--output`, в том числе при наличии символических ссылок.

## Повторный запуск и смена шаблона

При конфликте имён существующий файл другого или неизвестного трека сохраняется, а новая загрузка получает суффикс `[ID]`. Без `--overwrite` уже скачанный целевой файл пропускается. Если совпадающий трек и альбом найдены в другом месте внутри `--output`, Yamget переносит одну копию по новому пути. Перенос касается только треков текущего запроса и требует одной файловой системы с поддержкой жёстких ссылок. Остальные копии и старые пустые папки остаются на месте.

Чтобы применить новый битрейт к уже скачанному треку, укажите `--overwrite`.
