# Разработка и тесты

## Окружение

Из корня репозитория установите зависимости из lock-файла:

```bash
uv sync --locked --no-editable
```

Для ручного запуска CLI используйте команды из [руководства пользователя](USAGE.md). Чтобы увидеть, где менять разбор аргументов, очередь, загрузку или индекс, начните с [архитектуры](ARCHITECTURE.md).

## Запуск тестов

```bash
uv run --locked --no-editable python -m pytest
```

Для точечной проверки передайте нужные файлы:

```bash
uv run --locked --no-editable python -m pytest tests/test_index.py tests/test_relocation.py -q
```

Интеграционные тесты aria2 запускают локальный HTTP-сервер и требуют доступа к loopback. При отсутствии `aria2c` эти тесты пропускаются. Другой путь к исполняемому файлу можно задать через `YAMGET_TEST_ARIA2`.

Тесты не требуют токена Яндекс Музыки. Для ручной сквозной проверки с аккаунтом задайте токен и скачайте один доступный трек в отдельную папку. Проверьте MP3 и его теги. Автоматические тесты с локальным HTTP-сервером не проверяют загрузку через реальный аккаунт.

## Проверка кода

Для проверки изменённых Python-файлов используйте Ruff из окружения проекта:

```bash
uv run --locked --no-editable ruff check music_download/service.py
```

После изменения параметров CLI обновите [руководство пользователя](USAGE.md). Изменения в жизненном цикле загрузки и очереди описывайте в [архитектуре](ARCHITECTURE.md).
