# Yamget v0.1.0

CLI-загрузчик треков, альбомов и плейлистов Яндекс Музыки в MP3. Для загрузки используется aria2, для записи метаданных — mutagen.

## Требования и установка

- Python 3.11 или новее.
- uv.
- aria2 с исполняемым файлом `aria2c` в PATH для скачивания аудио.

Из корня Yamget:

```bash
uv sync --locked --no-editable
uv run --no-editable music-download --help
```

aria2 устанавливается отдельно системным пакетным менеджером. Например, для Arch Linux:

```bash
sudo pacman -S aria2
aria2c --version
```

Приложение не устанавливает системные программы автоматически.

## Использование CLI

Задать токен в текущем терминале без отображения и сохранения значения в истории bash:

```bash
read -rsp 'Yandex Music token: ' YANDEX_MUSIC_TOKEN
export YANDEX_MUSIC_TOKEN
printf '\n'
```

```bash
uv run --no-editable music-download 123456
uv run --no-editable music-download 'https://music.yandex.ru/album/123/track/456'
uv run --no-editable music-download 'https://music.yandex.ru/album/123'
uv run --no-editable music-download 'https://music.yandex.ru/playlists/12345678-1234-5678-9abc-123456789abc'
uv run --no-editable music-download --playlist 12345678-1234-5678-9abc-123456789abc
# Прежний формат с владельцем также поддерживается:
uv run --no-editable music-download --playlist 1000 --user USER
uv run --no-editable music-download 123456 --output ./downloads --bitrate 320
uv run --no-editable music-download 123456 --overwrite
```

### Шаблоны путей

`--output` задаёт корень загрузки, `--path-template` — путь внутри него без расширения.
По умолчанию используется `{title}`: все треки сохраняются в одну папку.

```bash
uv run --no-editable music-download 'ссылка' --output ./music \
  --path-template '{artist}/{album}/{track_number:02d} - {title}'
```

Пример результата: `music/Исполнитель/Альбом/03 - Песня.mp3`.

Доступны поля `{artist}` (первый исполнитель трека), `{album}`, `{title}`, `{track_id}`,
`{album_id}`, `{year}`, `{track_number}`, `{disc_number}`. Числа можно дополнить нулями:
`{track_number:02d}`, `{year:04d}`. Номер трека и диска берётся из выбранного альбома.
Если метаданных нет, используются `Unknown artist`, `Unknown album`, `track`, `unknown`
для ID альбома и `0` для чисел. Поле плейлиста пока не поддерживается.

Названия очищаются через `pathvalidate`; слеши в метаданных не создают подпапок.
Шаблон использует `/` как разделитель; абсолютные пути, `..` и неизвестные поля
отклоняются. Путь через существующие символические ссылки также должен оставаться
внутри корня загрузки. Конфликты имён, пропуск и `--overwrite` работают в итоговой
подпапке. Временный файл создаётся рядом с итоговым MP3.

Сервис записывает теги после передачи аудио и затем переносит файл на итоговый путь.

## Проверки

```bash
uv run --locked --no-editable python -m pytest
```

Интеграционные тесты используют aria2 и локальный HTTP-сервер. Если `aria2c` отсутствует, эти тесты пропускаются. Путь к исполняемому файлу можно задать через `YAMGET_TEST_ARIA2`. Загрузка с реальным аккаунтом Яндекс Музыки и тегирование скачанного аудио ещё не проверены.

## Жизненный цикл движка и очереди

`DownloadQueue.run()` запускает один `Aria2Engine` и закрывает его после обработки очереди, ошибки или прерывания. При досрочном прекращении обхода итератора используйте `contextlib.closing(queue.run(...))`; CLI уже делает это. Повторный одновременный запуск той же очереди запрещён.

Очередь пока обрабатывает задания последовательно. Прямая ссылка запрашивается перед началом каждого задания. Движок передаёт её через `aria2.addUri`, получает GID и опрашивает `aria2.tellStatus`. Ошибка отдельной загрузки не останавливает следующие задания. После передачи аудио сервис записывает теги и переименовывает временный файл; только затем очередь выставляет `completed`.

`queue.pause(job)`, `queue.resume(job)` и `queue.cancel(job)` доступны программному потребителю во время выполнения очереди (например, из потока управления будущего TUI). `job.gid` и `job.progress` содержат идентификатор передачи, полученные/общие байты и скорость; неизвестный размер представлен `None`. Пауза и продолжение относятся к передаче аудио. Отмена ожидающего задания исключает его загрузку; отмена при обработке метаданных проверяется между операциями и перед публикацией файла. Сами синхронные запросы метаданных и запись тегов не прерываются посередине.

RPC слушает loopback, использует случайный секрет из временного конфигурационного файла с правами `0600`. Секрет и подписанные ссылки не передаются в аргументах процесса. Ожидание RPC и остановка процесса ограничены таймаутами; зависший процесс принудительно завершается и ожидается. Сообщения ошибок RPC не выводятся напрямую, поскольку могут содержать ссылки и токены.

Загрузчик сохраняет только MP3. `--bitrate` задаёт желаемый битрейт: если он недоступен или не указан, выбирается максимальный доступный битрейт MP3.

По умолчанию имя аудиофайла — `Название.mp3`; исполнитель записывается в метатеги. Если имя занято другим треком, используется `Название [ID].mp3`. ID существующего MP3 определяется по ссылке Яндекс Музыки в тегах WOAF. Файл без определяемого ID также сохраняется без перезаписи: новая загрузка получает имя с ID.


### Индекс в памяти и перенос файлов

Перед командой скачивания Yamget один раз сканирует MP3 в `--output` и создаёт
индекс SQLite в памяти. Файл базы на диске не появляется; после команды индекс
удаляется. Следующий запуск заново видит ручные изменения в папках.

Если трек из текущего запроса уже есть в другой папке, он переносится по новому
`--path-template` без загрузки и перезаписи тегов. Совпадают ID трека и выбранного
альбома из WOAF; при нескольких копиях выбирается первая по пути. Остальные файлы
не перемещаются. `--overwrite` по-прежнему означает повторное скачивание.

Для переноса нужны одна файловая система с поддержкой жёстких ссылок и свободный
целевой путь. При обрабатываемой ошибке или Ctrl+C выполняется попытка отката.
Если откат не удался, лог содержит оба пути для ручной проверки. После аварийного
завершения восстановления нет; могут остаться два имени одного файла. Пустые
папки после переноса не удаляются.
